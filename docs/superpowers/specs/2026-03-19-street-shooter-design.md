# 街头生存射击游戏设计说明

**日期：** 2026-03-19

## 目标

将当前 `cat-box-game` 项目改造成一个单屏俯视角街头生存射击游戏。

玩家操控一名街头角色，在城市街道场景中跟随鼠标平滑移动，并通过按住鼠标左键持续开火来清理前方波次敌人。地图中会放置开局可拾取枪械和固定弹药补给点，玩家需要在有限弹药上限内完成生存战斗。

## 核心体验

- 街头风格背景，带有道路、路障、箱子、喷漆墙面、废弃车辆等元素
- 玩家角色平滑跟随鼠标位置移动，不能出现生硬的点按式位移
- 按住鼠标左键持续射击，不采用单击一发的主交互
- 敌人按波次从前方街道入口刷新，持续向玩家逼近
- 开局出现多把枪供玩家选择和拾取
- 地图固定位置提供不同数量或类型的弹药补给
- 地图中偶尔放置可进入坦克，玩家进入后可使用坦克炮攻击
- 坦克炮弹通过专用补给点拾取，不与普通枪械弹药混用
- 弹药上限明显高于试验值，但仍受限制，第一版建议上限为 `120`
- 整体操作和表现以“顺滑”为第一优先级

## 第一版玩法规则

### 1. 玩家移动

- 玩家角色会持续朝鼠标所在位置移动
- 移动采用平滑跟随，不使用瞬移
- 角色速度固定，后续如有需要再加入冲刺或加速机制

### 2. 射击方式

- 按住鼠标左键时持续开火
- 武器根据自身射速自动发射子弹
- 子弹从玩家当前位置朝目标方向飞行
- 子弹命中敌人后造成伤害并触发命中反馈

### 3. 武器系统

第一版提供三把开局可拾取武器：

- 手枪：稳定、省弹、单发输出适中
- 步枪：持续火力强、射速快、弹药消耗较快
- 霰弹枪：近距离爆发高、单次耗弹更多

规则：

- 开局场景中放置三把枪
- 玩家靠近武器后自动拾取并切换当前武器
- 第一版不强制加入复杂背包系统，默认只持有当前武器即可

### 4. 弹药补给

- 地图上有若干固定弹药点
- 不同弹药点提供不同数量的弹药
- 弹药总持有量不能超过 `120`
- 超出上限的拾取部分直接丢弃

弹药点示例：

- 路边补给箱：中等补给
- 废车旁弹药袋：较多补给
- 巷口小补给点：少量快速补给

### 5. 敌人波次

- 敌人从画面前方或街道上侧入口刷新
- 每一波敌人数量逐渐增加
- 每一波敌人移动速度可小幅提升
- 敌人持续朝玩家当前位置追击

建议第一版节奏：

- 第 1 波：4 个敌人
- 第 2 波：5 个敌人
- 第 3 波：6 个敌人
- 第 4 波：7 个敌人

### 6. 坦克系统

坦克在第一版中的定位是“偶尔出现的强力载具”，不是整局唯一核心玩法。

规则：

- 地图中会放置 `1` 辆可进入坦克
- 玩家靠近坦克时可以进入坦克
- 进入坦克后，玩家改为驾驶坦克移动与攻击
- 坦克拥有独立的坦克炮弹库存
- 坦克炮弹需要通过专用补给点拾取
- 坦克炮命中时造成范围更大、伤害更高的攻击效果
- 第一版不做复杂的上下车动画，优先保证进入、驾驶和开火手感流畅

设计取舍：

- 坦克是战局中的优势工具，用来帮助玩家处理高压波次
- 玩家即使不进入坦克，也能用普通枪械完成整局
- 坦克数量先限制为一辆，避免第一版规则过重

### 7. 胜负条件

- 清掉所有波次敌人则获胜
- 玩家生命值降为 0 则失败

第一版先不把“弹药耗尽且无补给”做成强制失败条件，避免前期体验过于严苛。

## 场景与视觉方向

### 1. 场景风格

整体采用街头巷战风格，避免草地、童话或纯色背景。

推荐视觉元素：

- 深灰色柏油路面
- 斑马线与道路标识
- 路边护栏
- 垃圾桶和木箱
- 路灯与废弃车辆
- 停靠或损坏的街头坦克
- 墙体喷漆或街头涂鸦质感

### 2. 角色辨识度

- 玩家角色使用更亮、更醒目的主色
- 敌人统一使用高危险感配色
- 武器拾取物用不同轮廓和颜色区分
- 补给点带有明显高亮边框或发光提示
- 坦克与坦克炮弹补给使用更重、更工业化的视觉语言

## 顺滑手感要求

“顺滑”是第一版必须达成的核心标准。

重点要求：

- 玩家移动使用持续更新的速度插值或平滑追随
- 开火使用基于时间步进的连续射击逻辑
- 子弹飞行、敌人追击、命中反馈全部放入稳定游戏循环
- 受击、命中、拾取反馈要立即可见，但不出现明显卡顿
- 背景元素数量控制在合理范围，优先保证战斗流畅

## 界面设计

界面保持简洁，避免大面积遮挡战场。

HUD 显示内容：

- 当前武器
- 当前弹药 / 上限
- 坦克状态与坦克炮弹数量（进入坦克时显示）
- 玩家生命值
- 当前波次
- 击败敌人数

提示信息：

- 开局提示移动与射击方式
- 拾取武器提示
- 波次开始提示
- 胜利 / 失败结果提示

## 技术实现建议

延续当前项目技术栈：

- Vite
- Electron
- HTML / CSS / JavaScript

推荐沿用并扩展现有模块化结构，将游戏拆分为：

- `state`：玩家、敌人、子弹、武器、补给、波次、UI 状态
- `state`：玩家、敌人、子弹、武器、补给、坦克、波次、UI 状态
- `input`：鼠标位置、按键状态、持续射击输入
- `rules`：战斗规则、拾取规则、坦克进入规则、波次推进、胜负判断
- `world`：场景布置、武器点与补给点生成、坦克与敌人刷新
- `render`：街头背景、玩家、敌人、子弹、HUD 绘制
- `loop`：统一驱动更新与渲染
- `ui`：页面初始化、开局提示、结果面板

## 测试重点

第一版至少验证这些行为：

- 鼠标移动时玩家会平滑追随目标位置
- 按住鼠标左键时会持续射击
- 不同武器使用各自射速与耗弹规则
- 玩家靠近枪械时可以拾取武器
- 玩家靠近补给点时会正确增加弹药但不超过上限
- 玩家靠近坦克时可以正确进入坦克
- 坦克状态下可以正常发射炮弹
- 坦克炮弹补给会正确增加坦克弹药
- 子弹命中敌人后敌人会受伤或消失
- 敌人接触玩家时会扣除生命
- 一波敌人清空后会进入下一波
- 最后一波清空后触发胜利
- 生命值归零时触发失败

## 第一版范围控制

第一版先实现“可玩、顺滑、主题明确”的基础版本，不追求复杂系统。

第一版不做：

- 多武器背包与手动切枪菜单
- 复杂敌人 AI
- 技能树或角色成长系统
- 联机
- 商店系统
- 大地图切换
- 复杂剧情
- 正式美术资源导入流程
- 多辆坦克或坦克耐久改装系统

## 风险与取舍

本次改动属于玩法重构，不是简单换皮。

主要风险：

- 现有项目结构偏向旧玩法，需要重组状态和规则
- “顺滑”体验高度依赖循环、插值和输入处理实现质量
- 街头场景如果装饰过多，容易影响视觉清晰度和性能
- 坦克加入后，玩家状态切换与武器逻辑会更复杂

第一版取舍：

- 优先保证移动、射击、命中、波次推进的顺滑度
- 坦克先做成单辆、易进入、强火力的简化版载具
- 优先用程序绘制或轻量占位图形营造街头感
- 在可玩性稳定后再考虑更复杂的枪械系统和美术升级
